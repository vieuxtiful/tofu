## PHASE 3: VIDEO PIPELINE MATURITY

### 3.1 — Temporal tracking edge cases
Three edge case handlers added to the Braise tracker:

1. Occlusion handling (MAX_GAP_FRAMES=15): A tracked text that disappears for
   up to 15 frames and reappears at a nearby position reconnects to the
   original track. The dormant track's consensus history is preserved across
   the gap. After 15 frames, the reappearing text becomes a new track.

2. Rapid text change splitting (TEXT_CHANGE_SPLIT_THRESHOLD=0.6): When
   consecutive OCR readings on the same track have text similarity below 0.6
   (e.g., "SALE" → "CLOSED"), the old track ends and a new one begins. Only
   triggers when both observations have accepted OCR text. Minor OCR noise
   ("PHARMACIE" → "PHARMACLE", sim ≈ 0.89) does not split.

3. Birth/death smoothing (MIN_CONFIRM_OBSERVATIONS=2): New tracks start in a
   pending state and must accumulate 2 consecutive observations before being
   confirmed. Pending tracks that miss before confirming are dropped as
   flicker-induced false tracks.

Files: src/tofu/video/temporal.py, src/tofu/video/analysis.py,
tests/test_video_temporal.py (13 new tests), tests/test_video_analysis.py
(6 new tests)

### 3.2 — VideoWorkspace frontend expansion
Expanded VideoWorkspace.tsx from 146 to 294 lines with 5 new features:

1. Enhanced timeline scrubber with keyframe and issue markers
2. Track list with confidence %, frame range, keyframe count, issue count,
   observation count, and enable/disable toggle. Filter input for searching
   by text or ID.
3. Per-track style editing (opacity slider, text color picker) in a
   collapsible "Style overrides" section
4. Side-by-side preview comparison (original vs. localized)
5. Progress indicator with frame count, ETA, and cancel/resume controls

### 3.3 — Video integration tests (tests/test_video_integration.py)
13 end-to-end tests covering the full video job lifecycle: create job →
timeline → track update → keyframe override → cancel/resume → error paths
(404 for nonexistent job/timeline/track, 400 for out-of-range keyframe).
Uses FastAPI TestClient with synthetic tracks inserted directly into the DB.

### 3.4 — Video documentation
Added a "Video Pipeline" section to README.md (~90 lines) covering
architecture, Braise tracker, edge case handling, compositor, API usage
(curl examples), frontend usage, cancel/resume, and testing inventory.

Implication: The video pipeline now handles real-world edge cases (occlusion,
cycling digital signs, flicker false positives) that would have produced
garbled tracks in 1.0.0. The VideoWorkspace is a full editing interface, not
a proof-of-concept. Video jobs are tested end-to-end.

## PHASE 5: RELEASE INFRASTRUCTURE

### 5.1 — Docker (Dockerfile, docker-compose.yml, .dockerignore)
4 Docker images:
  - app: Python 3.13 slim + ffmpeg + EasyOCR + FastAPI (port 8000)

## IMPLICATIONS FOR THE v1.0.0 RELEASE

1. **Production readiness**: The PyPI classifier change from Beta to
   Production/Stable signals that the API surface is stable and the test
   coverage is sufficient for production use. The 1,698-test suite runs on
   every push across 4 Python versions and 2 OSes.

2. **Deployment story**: `docker compose up` runs the full stack. The
   frontend is a static nginx bundle with a configurable API backend
   (VITE_API_URL). The three-venv architecture is preserved as optional
   sidecars with profile-based activation.

3. **Release pipeline**: Tagging `v1.0.0` triggers an automated release:
   wheel + sdist built, Docker images pushed to GHCR, GitHub Release created
   with CHANGELOG entry and downloadable artifacts. PyPI publish is opt-in
   via a secret.

4. **Video pipeline maturity**: The Braise tracker now handles occlusion,
   cycling digital signs, and flicker false positives — the three edge cases
   that would have produced garbled tracks in 1.0.0. The VideoWorkspace is a
   full editing interface with timeline, track list, style editing, preview
   comparison, and progress controls.

5. **Documentation completeness**: Every API endpoint is documented in
   docs/api.md (auto-generated, CI-checked). The architecture is visualized
   in docs/architecture.md with 7 Mermaid diagrams. CONTRIBUTING.md covers
   the full contributor workflow. CHANGELOG.md tracks every release.

6. **LLM comparison**: The README now quantitatively compares ToFU against
   Gemini and ChatGPT image generation, using ground-truth-scored metrics
   (recall, edit distance) rather than screenshots alone. The comparison
   makes clear that ToFU preserves the scene while LLM generators fabricate
   it.

7. **Playground**: The Gradio playground tracks the v1.0.0 tag and displays
   the version in the UI. It links to the new documentation.
