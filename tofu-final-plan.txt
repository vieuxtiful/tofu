# ToFU v1.0 Roadmap

A phased plan to take ToFU from 1.0.0 beta to 1.0.0, addressing every gap
identified in the completeness assessment (scored 8.3/10). Phases are ordered
by dependency — each builds on the previous.

================================================================================

## Phase 0: Pending Quick Wins (1-2 days)

Items already scoped from previous sessions that should be closed before
starting new work.

### 0.1 — Caret vertical offset in Basil menu input fields
- Problem: The blinking caret in Basil menu input fields has a vertical
  offset misalignment.
- Files: frontend/src/uikit.css, frontend/src/AnimatedCaretTextArea.tsx
- Task: Investigate the caret positioning CSS (likely a line-height / padding
  mismatch between the textarea and the animated caret overlay). Align the
  caret's vertical position with the text baseline.
- Success: Caret blinks at the correct vertical position in both light and
  dark themes, across all Basil input fields.

### 0.2 — Merge confidence recalculation
- Problem: POST /api/manifest/{asset_id}/regions/merge computes confidence as
  a simple arithmetic average, ignoring region size. A tiny low-confidence
  fragment drags down a large high-confidence region equally.
- Files: server/main.py (merge endpoint, ~line 2785),
  src/tofu/layers/cicerone.py (reread_merged_region, already implemented)
- Task:
  1. Replace sum(confs) / len(confs) with an area-weighted average:
     sum(conf * area) / sum(area) using each member's bbox.
  2. Optionally wire reread_merged_region as an opt-in reread: true flag on
     the RegionMerge request model (the function exists and has quality
     gates — it just needs a caller). When re-read succeeds, use its
     confidence; when it falls back to joined, use the area-weighted average.
  3. Update the mergeRegions docstring in frontend/src/api.ts to reflect the
     new behavior.
- Success: Merged region confidence reflects the dominant region's
  contribution. Re-read path produces honest None confidence when quality
  gates fail, rather than a misleading average.

## Phase 1: Developer Infrastructure & Code Quality (3-5 days)

### 1.1 — AGENTS.md
- File: AGENTS.md (new, repo root)
- Content: Build commands (npx tsc --noEmit, pytest, ruff check, mypy
  src/tofu), test commands, project structure overview, the three-venv
  architecture, known gotchas (OpenCV duplicate wheel bug, PYTHONUTF8=1 on
  Windows, PaddleOCR out-of-process requirement).
- Success: A new contributor (or agent) can build, test, and run the project
  from this file alone.

### 1.2 — CI/CD pipeline (GitHub Actions)
- File: .github/workflows/ci.yml (new)
- Jobs:
  1. lint — ruff check src/ tests/ server/ + ruff format --check
  2. typecheck — mypy src/tofu + npx tsc --noEmit (frontend)
  3. test — pytest tests/ --tb=short (skip paddle-live and inpaint tests
     via markers)
  4. build — pip install -e ".[server]" + cd frontend && npm run build
     (verify both build)
- Matrix: Python 3.11, 3.12, 3.13 on ubuntu-latest and windows-latest
- Cache: pip wheels, npm modules
- Success: Every PR runs lint, typecheck, test, and build. Red CI blocks
  merge.

### 1.3 — Pre-commit hooks
- File: .pre-commit-config.yaml (new)
- Hooks: ruff (lint + format), mypy (on staged Python files), tsc (on staged
  .tsx/.ts files via a local hook)
- Success: Local commits are linted and typechecked before they reach CI.

### 1.4 — App.tsx decomposition
- Problem: App.tsx is 6,335 lines — a monolith that holds all state, API
  calls, UI rendering, and event handlers.
- Approach: Extract by concern, not by component. Each extraction is a
  separate PR to keep diffs reviewable.
  1. Custom hooks — useSemanticUnits.ts (semantic state + all onSemantic*
     callbacks), useManifest.ts (region CRUD), useRender.ts
     (render/approve/preview), useProjects.ts (project lifecycle),
     useGlossary.ts, useVideoJob.ts, useInpaint.ts. Each hook owns its slice
     of state and API calls, returns state + handlers.
  2. Tab components — CaptureTab.tsx, TranslateTab.tsx, RenderTab.tsx,
     VerifyTab.tsx. Each receives its hook outputs as props. App.tsx becomes
     the shell: project gate, stepper, tab routing, theme, toasts.
  3. Shared state — Lift only truly cross-tab state (asset, project, theme,
     toasts) into App.tsx. Everything else lives in its hook.
- Target: App.tsx under 1,500 lines. Each hook under 500. Each tab under 800.
- Success: npx tsc --noEmit passes after each extraction. No behavioral
  change — pure refactor.

### 1.5 — Image protocol type
- Problem: 91 parameters typed Any for images crossing layer boundaries.
  mypy can't catch image type errors.
- Approach: Define a Protocol (or ABC) in src/tofu/core/types.py:

      class ImageAsset(Protocol):
          @property
          def array(self) -> np.ndarray: ...
          @property
          def pil(self) -> Image.Image: ...
          # or a simpler union: ImageAsset = Union[Image.Image, np.ndarray]

  Replace Any image parameters with ImageAsset across all layer modules. Add
  a runtime adapter if layers expect different concrete types (PIL vs
  ndarray).
- Files: src/tofu/core/types.py, all src/tofu/layers/*.py (signature changes
  only)
- Success: mypy strict mode passes for image parameters. No runtime behavior
  change.

## Phase 3: Video Pipeline Maturity (4-5 days)

### 3.1 — Temporal tracking edge cases
- File: src/tofu/video/temporal.py
- Tasks:
  1. Occlusion handling — when a tracked text disappears for N frames then
     reappears at a nearby position, maintain track identity rather than
     spawning a new track. Add a max_gap_frames parameter to settle().
  2. Rapid text change — when OCR text changes significantly between
     consecutive keyframes on the same track (e.g., a digital sign cycling
     messages), detect the change and split the track at the boundary rather
     than averaging dissimilar observations.
  3. Track birth/death smoothing — require K consecutive observations before
     confirming a track birth, and K consecutive misses before declaring
     death, to suppress flicker-induced false tracks.
- Tests: Add cases to tests/test_video_temporal.py for each edge case.
- Success: Temporal tracking handles occlusion, text changes, and flicker
  without spurious tracks.

### 3.2 — VideoWorkspace frontend expansion
- File: frontend/src/VideoWorkspace.tsx (146 lines -> target ~600)
- Tasks:
  1. Timeline scrubber — visual timeline with keyframe markers,
     click-to-seek, play/pause.
  2. Track list — per-track panel showing source text, target text,
     confidence, keyframe count, enable/disable toggle.
  3. Per-track editing — edit target text for a track, propagate to all
     keyframes. Edit style overrides per-track.
  4. Preview comparison — side-by-side or toggle view of original vs.
     composited frame.
  5. Progress indicator — job progress bar with frame count, ETA, cancel
     button.
- Success: Video workspace is usable for real video localization, not just a
  proof-of-concept.

### 3.3 — Video integration tests
- File: tests/test_video_integration.py (new)
- Scope: End-to-end: create video job -> analyze -> plan -> compose -> verify
  output exists and has correct duration/codec. Test cancel/resume. Test
  keyframe override.
- Success: pytest tests/test_video_integration.py passes with a real (small)
  test video.

### 3.4 — Video documentation
- File: README.md (new section after Memory)
- Content: Video pipeline architecture, the Braise analysis flow, temporal
  tracking, compositing, keyframe model, how to run video jobs via API and
  frontend.
- Success: README covers video as thoroughly as the image pipeline.

## Phase 5: Release Infrastructure (3-4 days)

### 5.1 — Dockerfile (multi-stage)
- File: Dockerfile (new), docker-compose.yml (new)
- Stages:
  1. app — Python 3.13 slim, installs tofu-l10n[all] from source, runs
     uvicorn on port 8000. Includes EasyOCR but NOT PaddleOCR/LaMa (they need
     their own interpreters).
  2. frontend — Node 20, builds Vite production bundle, serves static files
     via nginx on port 80 (proxies /api to app container).
  3. paddle (optional, in docker-compose) — Python 3.10 with paddlepaddle +
     PP-OCRv5, runs scripts/paddle_worker.py as a sidecar.
  4. inpaint (optional, in docker-compose) — Python with CUDA torch + LaMa,
     runs scripts/inpaint_lama_runner.py as a sidecar.
- docker-compose.yml — orchestrates app + frontend + paddle + inpaint with
  health checks and volume mounts for uploads/fonts/memory.
- Success: docker compose up runs the full stack with all backends.
  docker compose up app frontend runs the degraded path (EasyOCR only).

### 5.2 — Version bump 1.0.0 -> 1.0.0
- Files: src/tofu/__init__.py (__version__), pyproject.toml (classifier ->
  Development Status :: 5 - Production/Stable), CHANGELOG.md (1.0.0 release
  entry)
- Success: pip show tofu-l10n reports 1.0.0. PyPI upload (if applicable) is
  tagged.

### 5.3 — Release workflow
- File: .github/workflows/release.yml (new)
- Trigger: Git tag v*.*.*
- Jobs:
  1. Build Python wheel + sdist (python -m build)
  2. Build frontend production bundle
  3. Build Docker images (app, frontend, paddle, inpaint) and push to GHCR
  4. Create GitHub Release with CHANGELOG entry + wheel + sdist artifacts
  5. (Optional) Publish to PyPI
- Success: Tagging v1.0.0 produces a GitHub Release with installable
  artifacts and Docker images.

### 5.4 — Frontend production build config
- File: frontend/vite.config.ts (verify/adjust production settings)
- Tasks: Ensure API proxy is configurable via env var (VITE_API_URL), enable
  source map generation for production, configure asset hashing, verify
  npm run build produces a deployable static bundle.
- Success: npm run build produces a dist/ folder that can be served by any
  static file server with a configurable API backend.

### 5.5 — Playground sync
- File: playground/app.py, playground/requirements.txt
- Tasks: Update playground to use the latest API surface (Basil semantic
  units, video jobs if feasible in Gradio). Sync README. Verify Hugging Face
  Space deployment works.
- Success: The Gradio playground demonstrates 1.0 features and builds cleanly.
